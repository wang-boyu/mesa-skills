# Source map

Optional worker-owned traceability aid when several sources or material
behaviors make the existing specification difficult to follow. Adapt the
columns to the model, remove unused prompts, and keep a single record of each
fact. A table in the model specification is equally suitable; stable IDs and
a separate file are not required.

## Fidelity scope

State the intended paper, implementation, outcome or explicit hybrid fidelity
and the model/source versions or locators that bound the comparison. Explain
which source governs a material component when authorities differ.

## Behavior traceability

| Material behavior | Source and location | Interpretation and authority | Actual module or symbol | Check or evidence | Discrepancy or uncertainty |
|---|---|---|---|---|---|

Include initialization, scheduling, stochastic choices, observables, stopping
and geographic semantics where consequential. A matching output alone does
not establish mechanism fidelity. Distinguish source statements, implemented
behavior and authorized decisions.

## Material gaps

Record missing or inaccessible evidence and conflicts affecting implementation
or evaluation. Link consequential choices to the [decision note](model_decisions.md)
or their location in the existing specification; adapt the link to the project's
actual record. Leave an unresolved authority question unresolved. Preserve
attribution and access limits without copying protected source material.
